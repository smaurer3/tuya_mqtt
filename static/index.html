What is Tuya Admin?

Tuya Admin is the onboarding and management UI for the local Tuya MQTT bridge running on this server. It does three jobs:

  1. Discovery — same end result as python -m tinytuya wizard, but in your browser. Talks to the Tuya Cloud to pull each device's local key, scans the network for IPs, and writes devices.json.
  2. Aliasing — assign a friendly variable name (e.g. stage_lights) to each device so you can use it in MQTT topics instead of the long random device ID. Original IDs keep working — alias resolution is additive.
  3. Testing — Send ON / OFF commands to any switch on any device, watch the gate card light up when state confirms back over MQTT.

MQTT Topic Format

DirectionTopicPayload
Command (in)tuya/{id-or-alias}/{switch}/seton / off
State (out)tuya/{id}/{switch}/state &
tuya/{alias}/{switch}/state		on / off (retained)
Backwards compatible: when an alias is set, state is published to both the alias topic and the raw-ID topic. Anything you've already wired against the ID keeps working.

Quick Start

  1. Enter Tuya Cloud credentials — Settings tab → Tuya Cloud Credentials. Get API key + secret from iot.tuya.com.
  2. Run discovery — Discover tab → Start Discovery. Watch the log. Takes ~25s.
  3. Restart the service — Discover tab → Restart tuya_mqtt service. The bridge picks up the new devices.json.
  4. Set aliases — Devices tab → type a name in the Alias field for each device → Save Aliases. Hot-reloads in tuya_mqtt within 2 seconds, no restart needed.
  5. Test — Click ON / OFF on the switch cards. The card lights up blue when the device confirms.
